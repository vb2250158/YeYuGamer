# YeYu Gamer

**仅供学习自动化编排。** YeYu Gamer 是面向 Windows 本机的实验性游戏工具编排器，用于研究如何连接不同助手、管理执行队列、处理人工接管，并用同次运行的证据复核结果。

目标是在配置完成后，通过“开始每日”依次执行所选游戏的每日任务。**目前尚未达成目标范围内 7 款游戏全部每日的一键自动实跑验收。** 单元测试通过、启动器出现、工具退出或 Adapter 已登记，都不能代替游戏内任务完成的验证。

游戏客户端与上游助手需要分别从官方或各自项目获取、安装和更新。账号、凭据、个人运行配置、日志、截图和其他运行证据均不进入公开仓库。

## 从这里开始

先读 [架构说明](ARCHITECTURE.md)、[本机开发与验证](docs/local-development.md) 和 [版本记录](CHANGELOG.md)。已安装的单一 `YeYuGamer.exe` 提供 Manager、WebGUI 和生命周期管理；Manager 是运行状态的唯一写入者。

日常使用流程：

1. 在“今日”页面展开一个游戏。
2. 填写游戏路径和工具路径，并配置该工具暴露的参数。
3. 勾选今天要做的具体步骤。
4. 点击顶部“开始每日”，查看当前游戏、步骤与阻塞原因。
5. 遇到人工门时，队列暂停并保留现场。完成必要的人工操作后，从界面释放接管并恢复原运行。

每次启动一款游戏前，Manager 自动关闭同一批次范围内的其他已配置游戏，包括开始每日之前就已打开的客户端。原生游戏正常结束或普通失败后，也按本次绑定关闭当前客户端，包括队列中的最后一款。它先请求正常退出，再做有界清理；仍有残留或无法核实进程身份时，会显示原因并停止后续启动。人工接管和主动取消时保留现场。

完成判断需要同次逐 Todo 事件、截图和游戏语义复核。只有通过 CompletionReview/Adjudication、得到 `accepted_done` 的项目才能作为完成结果；待复核和未运行项目保留各自状态。

## 鸣潮多账号（0.3.4，待实机验收）

鸣潮可以为同一客户端配置多个已记住的账号，按列表顺序执行。先由用户在官方客户端完成登录并保留账号，再在鸣潮配置区填写账号别名、启用状态和登录页显示的**精确掩码标签**。别名仅供区分，不是登录身份；不要填写密码、验证码、UID、Token 或 Cookie。

- 新账号由 Manager 分配稳定的 `accountId`。每个启用账号分别建立 Run、Todo 与证据范围，账号 A 的完成记录不能用于账号 B。
- 当前所有鸣潮账号共享已勾选的每日步骤和 OK-WW 工具参数；账号列表顺序决定同游戏内的执行顺序。
- 开始每日时冻结账号范围与配置。后来修改启用状态、别名或顺序，不改变已经创建的批次。
- 旧版本的默认账号及历史记录会保留。账号一旦已有冻结的执行 Run，就不能更换登录标签；需要换号时新增账号并停用旧项，不覆盖旧账号身份。
- 切换遇到登录、条款、验证码，或标签缺失、重复、匹配不明确时暂停并保留现场。只有本次账号选择通过后，才能进入其每日步骤；恢复仍沿用原运行。

多账号配置、隔离和切换的离线测试不等于游戏验收。**当前尚未完成真实多账号每日，也未完成全部目标游戏每日的实跑验收。** 账号选择通过同样不代表每日完成，仍需逐账号满足完成合同。

## 目录

| 目录 | 内容 |
| --- | --- |
| `backend/` | Manager：配置、队列、运行状态与本机 API |
| `webgui/` | 配置、今日步骤、队列和运行状态界面 |
| `adapter-host/` | 单游戏工具的配置映射、启动和埋点转发 |
| `platform/` | 单宿主 `YeYuGamer.exe`、启动脚本与诊断 CLI |
| `scripts/` | 本机构建、验证、安装与统一发布入口 |

## 当前状态与边界

项目包含多个游戏助手的 Adapter 接入。实际可执行范围以本机已安装并晋级的 Adapter、当前勾选项与 Manager 状态为准。不同游戏的启动、更新、识别和奖励领取仍有待验证的环节，当前版本适合有人观察和接管的实验环境。

**公开仓库暂不能独立构建 StarRail Adapter。** 该接入依赖未随仓库提供的、基于 GPL 上游的兼容字节码载荷；当前尚未提供它对应的完整可读源码和生成器。构建此 Adapter 需要经审计、来源及许可条件明确的本机兼容载荷，不能据此宣称所有 Adapter 均可复现。

游戏策略与具体操作由各上游助手负责。本项目不提供绕过反作弊、登录验证或验证码的能力。登录、验证码、条款、购买、抽卡、付费、不明成本、联机/PVP和不可逆选择均停在相应人工边界。

## 出问题先看哪里

Manager 的日志、逐次运行记录与截图保留在本机运行目录；优先通过 WebGUI、CLI 或受限 API 读取同次证据。运行目录不属于仓库内容。

提交问题时请提供软件版本、复现步骤、已脱敏的错误信息和必要环境说明。不要提交账号、密码、Token、Cookie、验证码、邮件配置、个人绝对路径、完整数据库、未脱敏日志或原始游戏截图。

## 本机发布

将源码放在本机磁盘的独立维护目录，在仓库根目录使用统一发布入口。公开源码不含 StarRail 所需载荷，可按本机依赖情况选择其他 Adapter 组，例如：

```powershell
.\scripts\Publish-YeYuGamerLocalRelease.ps1 -AdapterGroups Classic,OpenKuro,NTE,FGO,CZN,BD2
```

该命令会更新本机安装，请先阅读开发说明。所有维护改动写回源码目录；安装目录和发布快照是派生产物。源码、依赖、构建缓存与运行数据均留在本机，发布入口拒绝网络盘源码。省略 `AdapterGroups` 会请求默认全部组，仍需满足各组的本机依赖，包含上述 StarRail 限制。

所选候选测试通过后才安全停止旧版、事务安装新版，并由 Manager 执行诊断 Canary 与晋级。统一发布不会创建每日批次，也不会启动游戏。安装后仍需配置各游戏与上游助手，从 WebGUI“开始每日”做真实运行验收。

## 可选通知与定时任务

邮件通知与定时任务需要本机单独配置。定时触发只代表提交批次，不代表每日成功；游戏和助手需要可用的交互桌面。日志和通知可能包含画面或个人信息，分享前需自行脱敏。
