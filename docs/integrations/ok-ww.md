# 鸣潮（OK-WW）每日接入规范

> 本文定义 YeYu Gamer 如何编排本机 OK-WW 源码。它不定义鸣潮的游戏策略，也不替代 OK-WW 的自动化逻辑。

## 目标与边界

YeYu Gamer 是 OK-WW 的统一入口：用户在一个游戏卡片中配置路径、选择今天要做的真实步骤，随后由 Manager 按队列交给 Adapter 启动 OK-WW。OK-WW 自己负责进入游戏、画面识别、操作顺序、条件判断与错误。

当前映射以 OK-WW `v3.6.6` 的源码 `DailyTask` 为基线；YeYu Gamer 运行该工具源码，不把它改造成内置脚本。上游升级后必须先重新核对源码，再更新映射。

- 不绑定 Agent、Rabi 或任何外部常驻服务。
- Agent 如需修改配置，只能调用 Manager 的普通 API；它不参与执行长连接。
- 没有独立的“验证奖励”或“复核完成”每日项。每个步骤的完成、跳过或失败来自 OK-WW 的阶段事件。
- 未选步骤不得执行；额外任务也不得被当作每日 Todo 伪装。

## 游戏卡片

鸣潮卡片的折叠标题栏从左到右显示：

1. **滑轨开关**：是否纳入一键每日；开关在游戏名“鸣潮”之前，始终可见，点击不展开卡片。
2. **游戏名和 ID**：`鸣潮` / `WW`。
3. **摘要**：是否已纳入，以及已选择的每日项数量。

展开内容依次为：

1. 游戏路径和 OK-WW 工具路径；
2. OK-WW 每日参数；
3. “本日需要完成的项目”列表。每行有滑轨用于选做，显示操作 ID，最右侧只显示今天的状态。

路径、参数和步骤选择均由该游戏的“保存”提交给 Manager；开关和勾选不会直接改写今天的完成状态。

## 一键每日队列规则

一键每日没有“预检后换一个更容易跑的游戏”的分支。它只按游戏卡片的显示顺序处理同时满足下列条件的游戏：游戏滑轨为开启，且该游戏至少选中一项每日步骤。

- 每个被选中的步骤都是独立选择；不要求全选“必做项”，也不会因选择某一步而自动补选入口或其它步骤。
- “执行今日批次”只有在路径、参数、游戏开关和步骤选择均已保存到 Manager 后才可点击；按钮只读取已保存快照并创建批次，不采纳页面乐观草稿。
- Manager 将所选步骤原样交给 Adapter。某一游戏的某一步普通失败时，失败记录留在该行，默认批次策略继续后面的已选游戏；用户显式选择“故障后停止”或出现 `human_required` 时才停止自动接管并保留现场。
- 未选游戏、关闭滑轨的游戏和未选步骤都不会进入本批次。

## 参数映射

这些是 OK-WW 的运行参数，不是每日 Todo：

| YeYu Gamer 字段 | OK-WW `DailyTask` 含义 |
| --- | --- |
| `whichToFarm` | 体力路线：无音区、锻造挑战或模拟领域 |
| `tacetSuppressionNumber` | 无音区 F2 列表序号（从 1 开始） |
| `forgeryChallengeNumber` | 锻造挑战 F2 列表序号（从 1 开始） |
| `materialSelection` | 模拟领域材料：共鸣者经验、武器经验或贝币 |
| `farmNightmareNestForDailyEcho` | 是否需要梦魇巢穴补每日 |
| 额外任务 / 工具退出 | 不提供给每日面板；Manager 每次运行都强制关闭周常花园、额外声骸刷取、合成、传送刷图和工具退出。 |

## 今日步骤目录

当前 DailyTask 的真实阶段按此顺序展示和调度：

| 操作 ID | 页面文案 | 执行条件 |
| --- | --- | --- |
| `attach-world` | 经官方启动器进入大世界 | 每次运行的入口阶段 |
| `inspect-daily-progress` | 读取今日体力与活跃进度 | 每次运行的进度读取阶段 |
| `farm-nightmare-daily-echo` | 需要时刷梦魇巢穴补每日 | 由每日进度与梦魇参数决定 |
| `spend-waveplates` | 按配置路线消耗结晶波片 | 由体力路线参数与当前体力决定 |
| `claim-daily-reward` | 领取每日活跃奖励 | 当 OK-WW 判定需要领取时执行 |
| `claim-mail` | 领取邮件 | OK-WW 的邮件领取阶段 |
| `claim-battle-pass` | 领取战令免费奖励 | OK-WW 的战令领取阶段 |

“模拟领域 + 贝币”只是 `spend-waveplates` 的参数组合；“完成活跃任务”是多个真实步骤可能产生的结果；“领取 20/40/60/80/100”与“复核最终奖励”都不是独立步骤，因此不进入此表。

## 选择、埋点与失败定位

启动前，Adapter 把已选择的操作 ID 写入 OK-WW 的运行上下文。OK-WW `DailyTask` 仅对被选择的阶段执行，并在真实阶段边界写入 JSONL：

```text
started    该步骤开始
completed  该步骤完成
failed     该步骤失败，并带错误摘要
skipped    源码条件判断为无需执行，并带原因
```

Adapter 将事件关联到同一次 Manager Run 后逐项转发。因此页面能同时显示当前正在跑的游戏、当前步骤，以及失败发生的具体步骤；它不通过退出码、日志关键词或页面勾选去猜完成状态。

Manager 会在启动前覆盖上游的附加任务和退出开关为空/关闭；因此本次每日不会串入周常、额外声骸刷取、合成或传送刷图。

## 升级和维护规则

OK-WW 升级时，先检查 `DailyTask` 的实际阶段、参数和事件边界；再更新本页、步骤目录与 Adapter 映射。禁止为保持旧界面而保留不存在的 Todo，也禁止把新工具内部动作未经选择和埋点就展示为可单独执行的每日项。

技术验证只检查“选择能传递、事件能逐项回传、未选步骤不执行”的接入契约；不启动游戏来伪造每日完成。
