# 每日验收邮件

邮件正文按游戏和账号列出已完成或已执行的事项、必做事项进度、验收状态，以及一张领取截图。需要人工处理、执行失败和未开始会直接显示；步骤执行完但证据尚未通过验收时，保持“待验收”。

其余事项、其他截图、尝试记录、处理原因和完成合同保存在附件 `daily-report.html`。下载后用浏览器打开，每个账号的详情默认折叠；图片随附件嵌入，查看时不需要连接运行电脑。原始证据继续由 Manager 保留，附件使用经过校验的缩放副本。

正文使用 640px 单列和内联样式，适配手机宽度。详细折叠放在 HTML 附件中，是因为邮箱对 `details` / `summary` 支持不一致，部分客户端会展开或替换这些标签。[兼容性测试](https://www.caniemail.com/features/html-semantics/)；响应式宽度采用邮箱支持的 CSS 规则。[Gmail 官方说明](https://developers.google.com/workspace/gmail/design/css)

## 数据与截图归属

- Manager 在批次封存时冻结正文、详细报告和证据引用。发送或重试只读这份快照；不会重新运行游戏，也不会把当前配置写回旧邮件。
- 结果和附件覆盖按 `(gameId, accountId, runId)` 校验。一个账号的图不能填补另一个账号的缺图；旧单账号通知和已冻结邮件保持兼容。
- 领取图从该账号完成合同引用与封存白名单的交集中选择。优先明确的奖励画面；普通步骤结束图只有在精确匹配已完成的每日领奖 Todo、操作和证据引用时，才作为领取画面候选。邮件、免费战令或登录画面不替代每日领奖图。
- 截图类型和步骤事件本身不证明领取成功。只有 Manager 已验收的目标与纳入合同的证据才标为“已验收”；其余候选图标为“待复核”。没有领取图时直接注明，现场画面仍可保留在详细报告。
- SMTP 层只将正文实际引用的图片附为内嵌图片，其他图放入报告。报告只接受已通过附件校验的 PNG/JPEG 字节，不从路径重新找图，也不加载外部图片或脚本。发送时已失效的截图显示缺失说明。

本功能的离线模板、附件和浏览器预览检查不等同于真实邮件送达验收，也不等同于游戏每日完成。
