# 官方启动器更新排障

沿用 [每日主流程](../daily-workflow.md)。先分清自动化工具、启动器和游戏客户端三者的版本；Unity 引擎文件版本、修改时间或旧安装路径不能证明客户端业务版本。

通过官方版本信息和已绑定启动器核实是否需要更新。保存当前绑定和配置，确认无冲突运行；只使用官方启动器的下载、更新和校验流程，不手工解包游戏补丁，不为更新把游戏 EXE 绑定改成启动器。

操作前查看真实页面/窗口与归属。使用当前平台可用且支持的 UI 工具；CEF、Qt、UIA 或 CDP 方法取决于环境，不因旧技能示例绕过工具限制、不暴露不必要的调试端口、不照抄历史坐标。无法操作时记录阻塞。

更新中跟踪真实下载/校验进展；完成后核实官方版本与启动器就绪状态。启动器自更新可能退出并产生新 PID，要重新识别准确绑定；不要按进程名称批量强杀，也不要裸启游戏救队列。通过 Manager 的正常生命周期恢复。

遇条款、凭据或验证码保留现场。更新完成不等于每日完成，仍从 WebGUI 执行并读取官方任务终态。设计背景见 `docs/integrations/client-update-design.md`，旧案例只作线索。
